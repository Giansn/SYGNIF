## What this is

Two phases, the second following a mid-course redirection from the user.

**Phase 1 — build a 2D engine from scratch** (Python, stdlib only) to learn what
an engine does. Fixed-timestep loop, PCG32 RNG, swept collision, tile grid,
input edge detection, software rasteriser, PNG encoder over `zlib`, 5×7 bitmap
font, and Pong. Stopped mid-module when the user said *"pivot to real engine
preparation"*.

**Phase 2 — prepare for Unity/Unreal.** User chose "Unity or Unreal" without
picking one, and "all of it" for the deliverable, so both are covered.

The organising idea, which everything else follows from:

> **Gameplay logic lives in a library with no engine reference; the engine layer
> is thin adapters.**

Standard practice, and also what made the work provable in a container where
neither editor can be installed — Unity gameplay code is plain C#, Unreal's is
plain C++, and both compile and unit-test headlessly *if* they do not reference
the engine.

### ⚠ This will not work in a fresh container

`.NET 8 was installed into the ephemeral container by hand` and is **not** in the
repo or on the default PATH. A new session must reinstall it or the two C# steps
fail:

```bash
curl -sSL https://dot.net/v1/dotnet-install.sh -o /tmp/dotnet-install.sh
bash /tmp/dotnet-install.sh --channel 8.0 --install-dir "$HOME/.dotnet" --no-path
export DOTNET_ROOT="$HOME/.dotnet"; export PATH="$DOTNET_ROOT:$PATH"
```

`g++`, `clang++`, `cmake`, `ninja` and Python 3.11 were preinstalled. Details in
`realengine/TOOLCHAIN.md`.

## What is verified, and what is not

Stated precisely because the shim builds are easy to over-read.

**Verified.** All gameplay logic, in three languages. PCG32 emits a
byte-identical stream in Python, C# and C++ — the C#/C++ tests assert against
values generated by the Python original. Swept collision is cross-checked
against brute-force sampling in each language. The C++ core builds under both
g++ 13.3 and clang++ 18.1 with `-fno-exceptions -fno-rtti -Werror`, reporting
identical check counts.

**Not verified.** *No editor has ever been run.* The adapters compile against
hand-written shims, which checks types and syntax and nothing else. Specifically
unverified: everything behind UnrealHeaderTool (reflection, Blueprint exposure,
replication, property serialisation), Unity lifecycle order and
`[SerializeField]` serialisation, and all of rendering, assets, audio, physics
and the build pipeline. That last group is the majority of what using an engine
involves; it is laid out as open milestones in `LEARNING_PATH.md` stage 3.

## Decisions already made — do not re-litigate without new information

- **Engine-free core + thin adapters.** Enforced mechanically, not by
  convention: the Unity asmdef sets `noEngineReferences`, so adding a
  `UnityEngine` using directive to a core file is a compile error.
- **Unity over Unreal for this project.** 2D work favours Unity (Paper2D is
  neglected), and on Linux Unreal ships **no binary release** — only a source
  zip, so an editor means a 100 GB+ engine build against minutes for Unity.
- **Ball speed cap of 900 in Pong.** Chosen by measurement over 12 seeds, not
  taste; the table is in `games/pong.py`. Below it, two competent AIs lock into
  a rally that never ends.
- **Corner-to-corner AABB storage.** Convention-neutral, because the Python
  original was Y-down (framebuffer), Unity 2D is Y-up and Unreal is Z-up.
- **Hand-rolled C++ test harness, not GoogleTest.** Unreal game modules build
  with exceptions off; a framework expecting them would force them back on and
  the build would stop being representative.

## Traps for a successor

- **A shim can invent problems the real engine does not have.** `-Wshadow` once
  fired on locals named `Owner` because the shim named that member `Owner` where
  Unreal names it `OwnerPrivate`. Fix the shim, not the module code.
- **`sync-core.sh` before opening the Unity project**, or the core scripts are
  missing and it will not compile.
- **`file(GLOB)` without `CONFIGURE_DEPENDS`** already caused a green build that
  silently skipped a newly added source file. Both CMake projects now use it.
- **Build artifacts.** One `.gitignore` at `realengine/` covers `bin/ obj/
  build/`. 23 artifacts were committed once and had to be untracked; check
  `git ls-files gamedev | grep -E '/(bin|obj|build)/'` returns nothing.
- **`gamedev/out/` is gitignored** (bulk rendered frames). Curated images live in
  `gamedev/docs/images/`.

## Where the reasoning is written down

`gamedev/NOTES.md` is the bug journal — eleven entries, each a defect found by a
failing test or by looking at rendered output rather than by reading about it.
The ones most worth a successor's time: the accumulator that silently dropped a
tick (float frame times never land on tick boundaries), the collision `skin`
that scaled with speed, the Pong match between two competent AIs that could not
terminate, and the intercept predictor that was wrong by half a ball twice over.

It also records a side bias suspected in Pong, measured over 24 seeds three
ways, and *not* found — 13/11, 10/14, and exactly 12/12 with identical AI seeds.
"Fixing" it would have introduced a real one.
